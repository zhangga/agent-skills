# 阅读与提炼规范

面向同一份证据提供两种阅读深度：飞书简报让用户快速知道做了什么、哪些事情需要继续；详细档案让数周后的用户能理解当时的问题并找回解决方法。

## 飞书简报

- 标题用“工作简报”或“近 7 天工作回顾”，附易读日期。滚动 7 天不要误称自然周。首行写上海时间范围；重排旧报告注明“修订版”，不能暗示本日新增。
- 优先呈现 3～5 个最有价值的变化，但不强凑数量。按项目独立短段，以项目名加粗；每个项目通常 1～2 条，每条一个结论，约 30～70 字。少量项目可直接全部列出，次要进展合并到“其他进展”。
- 先写具体结果及意义。例如“DS 采集已有真实样本，完整性检查通过”，随后只保留支持判断的一个关键数字。大量测试数量、版本和实现名留在详情。
- “已验证”“已修改”“待验证”要对应具体工作，不能用一个绿色标识代表整个项目已完成。对代码已修改但部署待验证的事项，在同一句清楚限定。
- 待办集中成一个短列表，优先放影响继续推进的 2～4 项，写明项目和具体动作。建议与原会话明确提出的待办要可区分，不替用户虚构承诺或期限。
- 日报通常 400～700 汉字、周报/7 天回顾通常 800～1,400 汉字；按实际工作量调整，不为达到字数复述。避免宽表格、三级列表、整段日志、连续分号长句和裸 UUID。
- 末尾用一行说明覆盖范围，存在缺口时明示。用户要求的本机档案地址集中在末尾代码块，优先 `index.html`；原始记录可给相对目录 `runs/` 和 `enrichments/`，必要时再列完整路径。注明“复制到本机浏览器或资源管理器打开”，不要承诺手机可访问。
- Markdown 作为可迁移的文字稿保存，启用且已授权发送时默认按 [cards.md](cards.md) 生成 Card 2.0。卡片有清楚的项目区块、折叠详情和真实来源按钮；用户明确要求普通富文本时才使用 deliver.py 的 `--brief`。发送后回读，检查类型和内容；发送回执不等于用户已读或已点击。

## 详细档案

先写清事实，再组织版式。重要事项通常应能回答：为什么要做、怎么定位/处理、做了哪些取舍、验证了什么、留下了什么、还有什么未完成。细节必须来自原事件；缺少证据的字段省略，或在确有必要时明确“本次会话未记录”。

每个事项保留一句摘要和最新结果，在 `details` 中展开实质信息：

| 字段 | 写什么 | 避免什么 |
|---|---|---|
| context | 用户目标、问题现象、触发条件及影响 | 把标题换个说法 |
| approach | 关键排查证据、修改步骤及范围，顺序有意义时按顺序 | 复制所有工具输出或命令历史 |
| decisions | 选型与取舍的理由，放弃方案仅在影响后续理解时保留 | 把推测包装为已确认根因 |
| validation | 测试/实测的条件、结果、数据口径和证据级别 | 将隔离测试说成真实部署验收 |
| artifacts | 原文真实出现的文件、文档、补丁或提交及用途 | 猜文件路径，承诺历史文件仍可访问 |
| limitations | 尚未验证的部分、适用条件、剩余阻碍 | 模板化“注意风险”或无关警告 |

重要事项一般增加约 200～500 汉字的有效信息；简单事务可短，复杂排障可以更长。长度是参考，不是填充目标。不在多个字段重复同一句事实。

同一 item_id 的多次进展合成一个事项：最新状态和后续动作优先展示，历史按实际发生日期收在“历史进展”。早期阻碍被后来证据解决后，不得再列为当前阻碍；旧证据仍保留供追溯。状态标签只表示已经记录的阶段，不等于整个事项全部验收。

会话来源显示原会话标题、日期，必要时列相关事件；UUID 和原 JSONL 位置放来源详情中。原始工具数据和敏感内容不复制。文件路径是历史来源信息，未经检查不能声称当前还存在。

## 阅读入口

`index.html` 是离线可读的单文件，采用与飞书简报一致的蓝白分组风格。支持项目导航、关键词、状态、起止日期、最近 7/30 天和本周，以及进展时间排序。时间均按上海发生日，起止日期都包含；空白分开的关键词按 AND 匹配，覆盖每条进展的正文、详情、文件路径和来源会话标题。

日期、关键词与状态必须在同一条进展上同时命中，不能把旧记录的关键词与新记录的时间拼在一起。匹配旧进展时，卡片显示该进展并标注当前最新状态和日期；展开后保留完整历史。筛选写入页面 URL 的 fragment，刷新后可恢复；不上传搜索词或记录。文件位置可复制，网页链接只接受 http(s)。

视图由 `scripts/presentation.py` 生成，`assets/archive.css` 和 `assets/archive.js` 内嵌到输出 HTML，阅读时不依赖外部资源。所有文字经过转义；档案里出现的 HTML、脚本或日志均当作文本，不能执行。排版重建使用现有档案，不重新计数工作、不推进采集基线。

Markdown 保留项目目录、事项目录和相同内容层次；不依赖网页才能查询事实。`runs/*.json` 保存原始提炼记录，`enrichments/*.json` 保存补充详情，阅读视图可从这些文件重建。

完成前抽查关键项目和一条多日事项：最新结论正确，详情可追溯，历史状态未冒充当前状态；检查搜索、项目筛选和窄屏阅读。不把这些排版修订作为新工作进展重新入账。
